# 分組畫面改版規格：在主視窗逐組整理（給宋宇宸）

2026-10-18。取代 10/17 的分組對話框（`grouping_view.py`）。底層（`group_folder`、`delete_photos`）不用改。

## 為什麼要改

分組要解決的是「這幾張留哪張」，這要用眼睛比照片。現在的對話框做不到：

1. 只有檔名、分數、相似度 0.9416，**看不到照片**。
2. 對話框是 modal，點照片時預覽更新在被蓋住的主視窗。
3. **不能改推薦**：系統推薦 A、使用者想留 C，沒辦法。
4. 「選取非最佳」之後，22 張選取散在長清單裡，按刪除前看不到自己要丟哪些。
5. 使用者分不出「相似」和「連拍」，不知道該選哪個。

## 新的畫面

按「相似照片分組」後，**主視窗切換成整理模式**（不開新視窗），再按一次或按 Esc 離開。

```
┌ 左：組清單 ──┐┌ 中：大圖（現有的預覽元件，可縮放）──────┐┌ 右：分析結果 ┐
│ 12 組・已看 3 ││                                          ││ 現有的       │
│ ✓ 第 1 組 4 張││              目前這張的大圖              ││ show_result  │
│ ✓ 第 2 組 2 張││                                          ││              │
│ ▶ 第 4 組 4 張│├──────────────────────────────────────────┤│              │
│   第 5 組 2 張││ [保留·推薦] [丟掉] [丟掉] [丟掉]  ← 本組縮圖列 ││              │
└───────────────┘└──────────────────────────────────────────┘└──────────────┘
 全部 12 組：保留 12 張、丟掉 22 張              [移到資源回收筒（22）]
```

- **左邊**：組清單，「第 N 組（k 張）」，看過的組打勾。最上面一行寫「共 N 組・已看 M 組」。
- **中間上方**：目前這張的大圖，沿用現有的 `PhotoPreviewLabel`（可以滾輪縮放、拖曳），用來看清不清楚。
- **中間下方**：本組所有照片的縮圖並排。每張縮圖上：
  - 「保留」或「丟掉」標籤，丟掉的縮圖變灰
  - 綜合分（一位小數，和主畫面一致）
  - 推薦的那張多一個「推薦」標記
  - 一句說明，見下面「推薦說明」
- **右邊**：照現在的方式顯示目前這張的分析結果（`show_result`）。
- **最下面**：「全部 N 組：保留 X 張、丟掉 Y 張」和「移到資源回收筒（Y）」按鈕。

## 操作

| 動作 | 滑鼠 | 鍵盤 |
|---|---|---|
| 看組內某張的大圖 | 點縮圖 | ← → |
| 切換保留／丟掉 | 點縮圖上的標籤 | 空白鍵 |
| 下一組／上一組 | 點左邊清單 | Enter／↓ 下一組，↑ 上一組 |
| 離開整理模式 | 再按「相似照片分組」 | Esc |

- **預設**：每組只保留推薦的那張（`is_best`），其他是丟掉。
- 使用者可以改：換成留別張，或一組留兩張以上都可以。
- 改過的組在左邊清單標出來（例如「已調整」），讓使用者知道哪些不是照推薦。

## 推薦說明

不要再顯示「與推薦照片相似度 0.9416」，一般人看不懂。改成每張一句話，用資料庫裡已有的美感分、技術分（`get_photo(path)` 的 `aesthetic_score`、`technical_score`）：

- 推薦的那張：
  - 組內技術分最高 →「推薦：最清晰」
  - 否則組內美感分最高 →「推薦：構圖／美感最好」
  - 兩者都不是最高 →「推薦：綜合分最高」
- 其他張：「比推薦低 X 分」。如果它的技術分比推薦那張低 10 分以上，再加「、較模糊」。

**只能寫分數算得出來的事**。系統沒有偵測閉眼、表情，不能寫。

## 確認刪除

按「移到資源回收筒（Y）」時：

1. 如果有組被設成全部丟掉，先警告：「第 3、7 組全部都會丟掉，確定嗎？」
2. 跳出確認視窗，列出要丟的張數和前幾個檔名（照現有 `delete_selected` 的寫法）。
3. 確定後直接呼叫現有的 `delete_photos(paths)`：移到資源回收筒、RAW 的 `.xmp` 一起移。**不用再經過清單選取。**
4. 刪完照 `delete_selected` 收尾：`recompute_scores` 加 `refresh_list`，失敗的照片列出原因。
5. 刪完重新分組。還有組就留在整理模式，沒有組就自動離開並提示。

## 模式

- 預設只有一種：**相似**（`group_folder(folder, "similar")`）。
- 進階選項放一個勾選框「只看連拍（同相機、5 秒內）」，勾了改用 `"burst"`。不要再放兩個並列的模式讓人選。
- `not_ready`、`no_capture_time`、`exiftool_missing` 的提示照舊，顯示在組清單上方。

## 權重滑桿

整理模式中**停用權重滑桿**（工具提示寫「離開整理模式後才能調整」）。離開後調了權重，再進來就重新分組，選擇也重設。這樣不用處理「使用者改過的選擇遇到推薦換人」的情況。

## 分析完主動提示

批次分析結束時，如果這個資料夾分得出組，就在狀態列（`progress_label`）寫「找到 12 組相似照片，按『相似照片分組』整理」。**不要跳視窗。**

## 縮圖（效能重點）

RAW 完整解碼很慢，一組十幾張會卡住畫面，**一定要在背景執行緒做**：

- RAW 用內嵌的 JPEG 縮圖：`rawpy.imread(path).extract_thumb()`。本機實測 ARW 約 **20 毫秒／張**，`load_image` 完整解碼約 166 毫秒／張。
- **內嵌縮圖沒有轉正**，直拍的照片會是橫的。要照 EXIF Orientation 或 rawpy 的 `sizes.flip` 轉正，請用直拍的照片測。
- JPG、HEIC、沒有內嵌縮圖的 RAW：改用 `ai_inference.load_image` 再縮小（HEIC 已經會轉正）。
- 用 `QThreadPool` 或另一條 `QThread` 載入，載好用 signal 回主執行緒更新縮圖。載入中先顯示灰色方塊。
- 用路徑當 key 做快取，同一張不要重載。換資料夾時清掉快取。
- 大圖（中間上方）照現在 `show_photo` 的方式載入就好。

**驗收**：40 張 ARW 的資料夾，進入整理模式後第一組縮圖 1 秒內出現。整理過程中畫面不能卡住超過 0.3 秒。

## 程式結構

把「整理狀態」寫成不依賴 Qt 的類別，才好測試：

```python
# grouping_review.py
class GroupReview:
    def __init__(self, grouping, scores): ...   # grouping = group_folder() 的結果；scores = {path: (美感, 技術, 綜合)}
    def is_kept(self, path) -> bool
    def toggle(self, path)                     # 切換保留／丟掉
    def discard_paths(self) -> list            # 全部要丟的照片
    def all_discarded_groups(self) -> list     # 全部丟掉的組 id（確認前警告用）
    def adjusted_groups(self) -> set           # 使用者改過的組
    def reason(self, path) -> str              # 推薦說明那一句
    def summary(self) -> (kept, discarded)
```

- 畫面放在新檔案（例如 `grouping_review_view.py`），`main_v2.py` 只加切換模式的接線。
- 舊的 `grouping_view.py` 和它的測試改完後刪掉，不要兩套並存。

## 測試（至少）

1. 預設只有每組的 `is_best` 是保留。
2. `toggle` 之後 `discard_paths` 正確；一組留兩張也正確。
3. 全部丟掉的組會出現在 `all_discarded_groups`。
4. `reason`：最清晰／美感最好／綜合分最高三種推薦說明，以及「較模糊」的門檻。
5. 確認刪除時，傳給 `delete_photos` 的路徑剛好是 `discard_paths`（patch `delete_photos`，不要真的刪），刪完重新分組正確。
6. 縮圖：JPG、ARW（內嵌縮圖）、直拍的照片都會轉正。
7. 全套測試在 Windows 和 Mac 都要過：`python -m unittest discover -s tests -t .`
