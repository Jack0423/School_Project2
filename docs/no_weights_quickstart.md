# 沒有模型權重也能先做的事

## 執行已準備的檢查

在專案資料夾執行：

```bash
python tools/check_without_weights.py
```

每次會建立新的 `reports/no_weights/時間/`，內含 `tests.log` 與 `summary.json`。
這是特別選出的免權重測試，不是整個專案的全套驗收。

測試範圍包括：

- 真正的 Qt 背景執行緒、介面計時器、SQLite 寫入、單張及批次流程、失敗恢復。
- 四執行緒解碼與單執行緒推論的安排。
- 循序／平行分數比對與報表產生流程。
- 分組預設 0.85／5 秒、相機識別、小數秒時間解析、誤分和漏分統計。
- 模型介面形狀、影像轉換、資料集讀取規則、缺權重時確實報錯等保護。

Qt 與比較工具使用測試替身；分組使用合成特徵；模型形狀測試使用未訓練模型。
這些都不會替真實照片產生分數，也不代表實測的速度或準確率。
少數測試會明確跳過，理由記在報表中，不會計為通過。

## 目前電腦環境

專案 `.venv` 是供這台 Mac 使用的環境，沿用本機已安裝的 PyTorch、NumPy 等套件，另外安裝 PyQt6。
因此移到別台電腦要重新建立環境，不要打包 `.venv` 給組員。
原有 requirements 中的 CUDA 套件是 Windows／NVIDIA 開發機設定，不要直接在 Mac 安裝 `+cu128` 版本。

查看完整環境：

```bash
.venv/bin/python check_env.py
```

沒有兩個現役權重時，這支環境檢查仍會以失敗結束，這是預期結果。Mac 沒有 CUDA 也會提示，現有推論程式會使用 CPU。

## 接下來可先準備人工標註

目前專案沒有實際照片，所以尚未建立真實標註清單。先挑一個固定的驗證資料夾，包含：

1. 真正的連拍：同場景、同主體，時間相近。
2. 不同場景或主體：用來檢查程式有沒有誤分。
3. 外觀相似但時間相隔較久的照片：用來檢查時間條件。
4. 單獨照片：應該獨立一組。

先依照片內容人工記錄哪些照片同組，單張各給獨立組號。不要直接照程式分組結果標註。
之後拿到權重並完整跑一次批次分析，再用 `validate_grouping.py template` 產生有正式路徑的 CSV，把這份人工判斷填入。

拿到權重後的指令與驗證方式，見 [原交付說明](batch_handoff.md)。
